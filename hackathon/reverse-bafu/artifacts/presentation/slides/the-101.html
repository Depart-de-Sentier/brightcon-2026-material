For 51 out of the 138 we found additional information in the reports that we could use for the dis-aggregation.

The first job was deciding what to work on, and that started with counting. The ecoSpold export marks 101 datasets as system processes, and we started there. That flag turns out to be incomplete. If you ignore the flag and ask a structural question instead — does this dataset consume anything that is actually a production input, or only waste-treatment services and a plant unit — you find 37 more. Those are the old APME and PlasticsEurope eco-profiles: styrene, benzene, butadiene, the nylons, ABS, polycarbonate, the isocyanates. They confirm it in their own metadata, which the test never reads: their includedProcesses field says aggregated data from raw material extraction until delivery at plant. So we found 138, not 101, and there may be more: the structural test only catches datasets with no production input at all, so a partly aggregated dataset would still slip through. The box at the bottom is the honest summary. For each of the 138 we asked whether anything names its inputs well enough to work from: a table or text in the cited report, the dataset's own process description, or a unit process of the same product elsewhere in BAFU. For fifty-one it does, and those are the fifty-one we dis-aggregated. For the other eighty-seven there is either nothing, no report and metadata that is empty, generic or confidential, or only a partial hint: a feedstock named without an allocation, a supply mix, a list of field operations. Only twelve of the fifty-one print their inventory as a table we can transcribe, so a method that only reads tables would have finished with twelve. The classification per dataset, with the sentence it rests on, is in results/usable_information.csv.
