# Concept: Flow-Based Error Diagnosis for Reverse-BAFU Rebuilds

## 0. Goal and scope

**Goal:** For each rebuild, trace the deviation from the aggregated original back to **concrete model errors**: which technosphere input, which direct flow, which dataset choice, which methodology.

**Principle:** Diagnosis in **flow space** (elementary flows and activities). Impact categories are used only for reporting at the end.

**Why this is identifiable:** Cumulative inventories of inputs (`M = B·A⁻¹`) are strongly collinear, because they share the same upstream chains. The **direct** flow vectors of activities or sectors (columns of `B`) are much more distinguishable. The residual is therefore first decomposed onto **upstream sectors** and only then traced back to foreground inputs, rather than fitting inputs directly.

---

## 1. Notation

| Symbol | Meaning |
|---|---|
| `g ∈ Rᵐ` | cumulative inventory of the original (aggregated dataset), per functional unit |
| `a ∈ Rⁿ` | amounts of the foreground inputs of the explicit node |
| `M` | matrix of cumulative inventories of the inputs (column i = input i per unit) |
| `d` | direct flows of the node |
| `ĝ = M·a + d` | cumulative inventory of the model |
| `r = g − ĝ` | residual in flow space |
| `s = A⁻¹·y` | scaling vector of the model's supply chain (y = demand on the explicit node) |
| `B` | biosphere matrix (direct flows per activity) |
| `σ(j)` | sector assignment of activity j |
| `ĝ⁽ˢ⁾` | contribution of sector S to ĝ: `Σ_{j∈S} B[:,j]·s_j` |
| `ĝ⁽ⁱ⁾` | contribution of input i to ĝ (demand on input i only) |
| `P[i,S]` | activity of sector S in the model chain caused by input i |
| `C` | characterisation matrix (EF 3.1) |

### Starting point in matrix form

| | Original (system-terminated) | Model (explicit node) |
|---|---|---|
| A column | diagonal only (reference product = 1), no technosphere inputs | inputs `a` generated by the algorithm, linked to BAFU unit processes |
| B column | **cumulative inventory of the report authors' entire system** = `g` | direct flows of the plant only = `d` |
| Cumulative inventory | `g` (cumulative = direct) | `ĝ = B·A⁻¹·y` or `M·a + d` |
| Decomposable by sector/input | no | yes, via `A⁻¹` and `B` |

**Mandatory rule:** Always compare `g` with the **cumulative** `ĝ`, never with the model's B column (`d`). Comparing with `d` sets the whole system against the plant alone and flags almost everything as missing.

**Principle:** Only the model has structure. It is decomposed by sector and input, and the analysis estimates which weights on these building blocks best reproduce the single B column of the original. Deviations of these weights from 1 show which generated technosphere flows are wrong.

## 2. Error taxonomy and its signature in flow space

| Code | Error type | Expected signature |
|---|---|---|
| E1 | Wrong amount of an existing input | All sectors dominated by input i are shifted by **the same factor κᵢ** |
| E1u | Unit or conversion error | as E1, with κᵢ ≈ a known constant (10³, 3.6, heating value, density, t→kg) |
| E2 | Wrong dataset (location, technology, version, origin) | Sectors **within** the chain of input i shift inconsistently (e.g. coal ↑, waste fuel ↓) |
| E3 | Missing input | Sectors absent or under-represented in the model (μ_S > 0), not attributable to any existing input |
| E4 | Superfluous input | Sector excess (λ_S < 1) carried by a single input |
| E5 | Wrong direct flow (amount, missing, compartment) | Residual on flows that come only from `d` in the model |
| E6 | Double counting | Combustion dataset ("burned in …") **plus** the same emissions in `d` |
| E7 | Mapping / nomenclature error | Pairs in the residual: same substance, different key (UUID, compartment, biosphere DB), opposite sign |
| E8 | Allocation or scaling | All sectors shifted by the same factor α |
| E9 | Background version difference | Systematic shift of whole sector groups (e.g. electricity mix) across **all** inputs |

### Option: prioritised, slimmed-down taxonomy

Sorted by expected share of the deviation × frequency in evidence-based rebuilds.

| Rank | Class | Contains | Rationale |
|---|---|---|---|
| 0 | **Pre-processing: mapping** | E7 | Prerequisite for all modules, cheap, always runs first |
| 1 | **Missing input** | E3 | Most frequent and largest error; report tables usually list only main inputs (infrastructure, auxiliaries, disposal, additional energy are missing) |
| 2 | **Wrong dataset** | E2 | Acts on the entire upstream chain; systematic through the location preference in resolve; cannot be fixed by amount calibration |
| 3 | **Wrong amount** | E1, E1u (flag), E4 (as κ ≈ 0) | Frequent, usually small; unit errors are rare but large and easy to detect |
| 4 | **Wrong direct flow** | E5, E6 (double-counting check) | Direct flows are usually transcribed correctly; relevant mainly with "burned in" datasets |
| – | **Global check: allocation/scaling** | E8 | One parameter per dataset, not a model error |
| – | **Global check: background version** | E9 | Only if the original's background version is available |

Result: 4 hypothesis classes, 1 pre-processing step and 2 global checks instead of 10 error types.

**Priority by rebuild strategy** (as starting value for the evidence prior `p_h` in Section 4):

| Strategy | Order |
|---|---|
| S1 Transcription of a report table | Missing input > unit error > wrong dataset > amount |
| S2 Template transfer | Wrong dataset > missing input > amount |

If this option is chosen, the fault injection in Section 5 reduces to the four hypothesis classes plus E8.

### Mapping: algorithm step → error → analysis → signal

Each technosphere input leaves a characteristic fingerprint in the elementary flows through its upstream chain. The analyses translate deviations in these fingerprints back to the algorithm step that caused them.

| Algorithm step | Possible error | Analysis | Signal |
|---|---|---|---|
| Read evidence (report, primary source) | Source does not name all inputs | E (μ), K | Sector missing entirely; sibling processes have an input class that is missing |
| Select inputs | Input forgotten or superfluous | D, E | Tracer of a sector ≈ 0 in the model, or excess (λ < 1) |
| Assign dataset (resolve) | Wrong location, technology or origin | F (consistency), G | One input explains its sectors inconsistently; another dataset lowers the loss |
| Transfer amount and unit | Transcription or unit error | F (κ), H | All sectors of one input shifted by the same factor; κ ≈ conversion constant; energy gap per carrier |
| Set direct flows | Wrong compartment, double counting | H (carbon), I | Combustion CO₂ counted twice; λ_direct ≠ 1 |
| Map flows | Same substance, different key | B | Pairs "model only"/"original only" of the same substance |
| Calibrate | Fit compensates structural errors via amounts | A5, H | Physically impossible amounts; λ/κ unstable depending on flow selection |

**One-off or systematic:**
- **One-off:** a hypothesis affects only one dataset → fix in the spec.
- **Systematic:** the same hypothesis class occurs across many datasets → **error in the algorithm**. Examples:
  - many unit flags → unit parser or conversion
  - many location mismatches → location preference in resolve
  - infrastructure missing almost everywhere → rule "add infrastructure"
  - frequent double counting → include fuels as supply only when direct emissions come from the table
  - calibration systematically makes results worse → only fit after the structural check has passed
- Tool for this: **matrix dataset × hypothesis class** (count and ΔL) across all diagnosed datasets, additionally aggregated per algorithm step.
- Deviations caused by the original's methodology (allocation, background version) are separated by the global checks and **not** attributed to the algorithm. An incomplete primary source is reported as an evidence gap, not as a program error.

## 3. Analysis modules (order = execution order)

### Module B – Flow harmonisation and mapping audit (E7)
- Key per flow: `(normalised name | CAS, compartment, subcompartment, unit, biosphere DB)`.
- For all flows with `g_f = 0` or `ĝ_f = 0`, search for a partner with the same substance (name/CAS) and a different key.
- Output: list of pairs with amounts, CF difference and contribution to the category residual.
- Rule: merge pairs and run **all subsequent modules on the harmonised flow space**. Report the number of "model only" and "original only" flows before and after.

### Module A – Residual and flow selection

**A1 Relevance per category.** The maximum of original and model is used, so that model excesses are also captured:
`share_kf = |C[k,f]|·max(|g_f|,|ĝ_f|) / Σ_f' |C[k,f']|·max(|g_f'|,|ĝ_f'|)`

**A2 Selection as union** `F = F_imp ∪ F_phys ∪ F_tr`:
- `F_imp`: for each category k, the flows sorted by descending `share_kf` until cumulative coverage ≥ c is reached (default c = 0.97). Union over all k.
- `F_phys`: for each physical class (energy resources in MJ via heating value, land in m²a or m², water in m³, minerals in kg), the same coverage criterion on `max(|g_f|,|ĝ_f|)`. This captures uncharacterised but informative flows.
- `F_tr`: tracers from Module D, regardless of size. Since D depends on C, the selection is built in **two stages**: first `F_imp ∪ F_phys` for C and D, then the full `F` for E.
- Unselected flows are not used in the fits but are listed with their maximum `share_kf`.

**A3 One-sided flows** (g_f = 0 xor ĝ_f = 0, or |ρ_f| > ln 10³):
- do not include in the log fit
- pass to the mapping audit (Module B); if no partner is found, list as evidence for a missing or superfluous input (E3/E4) with share `share_kf`
- handle sign conflicts (g and ĝ with different signs) separately as well

**A4 Log ratio and weights:**
- `ρ_f = ln((ĝ_f + ε_f)/(g_f + ε_f))`, with `ε_f = 10⁻³ · max(|g_f|, |ĝ_f|)`. This bounds |ρ_f| at ≈ ln 10³ and stabilises flows near zero.
- Weight: `w_f = min( max(max_k share_kf, w_phys_f), w_max )`, with `w_phys_f` = share within the physical class and `w_max = 0.25`. The cap prevents a single flow (e.g. fossil CO₂) from dominating the fit.
- In Module E, use a **Huber loss** on the log residuals instead of squared loss (kink at ln 2). Individual outlier flows, such as undetected mapping errors, then do not distort λ and κ.

**A5 Stability check (mandatory):**
- Run Modules E and F with c ∈ {0.95; 0.97; 0.99} and additionally leave-one-category-out.
- Stable if `|Δ ln λ_S|, |Δ ln κ_i| < ln 1.2` for all reported sectors and inputs; the sign and existence of μ_S must not change.
- Flag unstable sectors and inputs and carry them into the hypothesis ranking with half the prior `p_h`.
- Output: number of flows per group, coverage achieved per category, stability table.

### Module H – Physical balances (CF-free)
1. **Energy by carrier:** primary energy resources (crude oil, natural gas, hard coal, lignite, uranium, hydropower, biomass, wind/solar) separately for g and ĝ. Remove known feedstock or geogenic shares (e.g. oil shale carbon) on **both** sides. Result: gap per carrier in MJ/FU.
2. **Carbon in the node:** C in direct CO₂/CO/CH₄/NMVOC versus C from (a) fuels burned in the node and (b) process CO₂ (calcination, geogenic). If inputs of type "…, burned in …" are present **and** `d` contains combustion CO₂ → check E6.
3. **Mass:** Σ material inputs (kg) versus product plus waste; stoichiometry where known (hydration, calcination, crystal water).
4. **Water:** turbined water and consumptive water separately.
5. **Optional, elements:** S (SO₂ versus S in fuel), heavy metals.
- Output: gaps per carrier or substance. Gaps > 20 % are mandatory hypotheses for Modules F and G.

### Module I – Direct flow check (E5)
- Direct flows `d` versus the report table (evidence from the spec): presence, amount, unit, compartment.
- Determine the share of direct flows in ĝ per flow; flows with a direct share > 80 % form their own group with its own factor λ_direct in Module E.

### Module C – Sector decomposition of the model chain
- Export the scaling vector `s` for the demand on the explicit node from `lci.System`.
- **Sector map** `config/sector_map.yaml`: activity → sector, via ISIC/CPC from ecoSpold plus name rules, 25–40 sectors, defined by **emission-generating technology**, not by product. Examples:
  - crude oil and gas extraction, refinery, hard coal mining, lignite mining, uranium mining and milling
  - coal, gas and oil power plants, nuclear, hydropower, wind/PV
  - clinker kiln, lime burning, quarrying/extraction, metal production (Fe, Al, Cu, Ni)
  - organic/inorganic chemicals, road/rail/ship transport
  - waste incineration, landfill, wastewater, agriculture, forestry
  - infrastructure/construction
- To compute:
  - `ĝ⁽ˢ⁾` for all S
  - `ĝ⁽ⁱ⁾` per input i
  - `P[i,S]` via separate demand per input: `s⁽ⁱ⁾ = A⁻¹·a_i·e_i`
- Identifiability: cosine similarity of the normalised sector fingerprints `ĝ⁽ˢ⁾/‖ĝ⁽ˢ⁾‖` in the active flow space. Merge sectors with similarity > 0.95 and report the condition number.

### Module D – Tracer catalogue
- Sector specificity per flow:
  - `π_model(S|f) = |ĝ⁽ˢ⁾_f| / Σ_S' |ĝ⁽ˢ'⁾_f|`
  - `π_db(S|f)`: the same over a database-wide reference demand (default: sum of the scaling vectors of all unit-process analogues of the 101 aggregated datasets; alternatively unit demand on all market activities).
- Tracer: `π_model ≥ 0.8` **and** `π_db ≥ 0.8` for the same sector.
- Pre-seeded candidates, to be confirmed empirically:

| Flow | Expected sector |
|---|---|
| Uranium, radon-222 | nuclear fuel chain |
| Lignite, phosphate to water | lignite mining |
| Halon-1211/1301 | oil and gas extraction |
| Turbined water | hydropower |
| Tl, Hg to air | clinker kiln, coal power |
| Land occupation, extraction site | quarrying |
| Cu, Ni, Mo ores | metals/infrastructure |
| PAH to water | refinery/coking |

- Output: tracer table with `g_f`, `ĝ_f`, ratio, sector and π values. This is the **first readable diagnosis**.

### Module E – Sector deconvolution (core)
Estimates by what factor each sector is active in the original relative to the model, and which sectors are missing from the model:

```
g_f ≈ λ_direct·ĝ_f^(direct) + Σ_S λ_S·ĝ_f^(S) + Σ_{S∈𝒮⁺} μ_S·b̄_f^(S)
```
- `b̄⁽ˢ⁾`: mean direct flow vector per unit output of representative activities of S. Needed for sectors that are missing or barely present in the model (`𝒮⁺` = sectors with `‖ĝ⁽ˢ⁾‖` below a threshold).
- Objective in log space, weighted:
  `min Σ_{f∈F} w_f·H_δ( ln(g_f+ε_f) − ln(ĝ_f(λ,μ)+ε_f) ) + α·Σ_S (ln λ_S)² + β·Σ_S μ_S`, with Huber loss `H_δ`, δ = ln 2, and F, ε_f, w_f from Module A.
  Constraint `λ, μ ≥ 0`. The ridge penalty pulls λ towards 1; the L1 penalty keeps the number of missing sectors small.
- Uncertainty: bootstrap over flows, stratified by relevance, B = 200. Output: 90 % CI for each λ_S and μ_S.
- Interpretation:
  - `λ_S ≈ 1` (CI contains 1): sector correctly represented
  - all λ_S ≈ the same α ≠ 1: E8 (allocation or scaling), continue with Module J
  - λ shifted only for one sector group (e.g. electricity mix) across all inputs: E9
  - `μ_S > 0` significant: E3 candidate, continue with Module F
  - `λ_direct ≠ 1`: E5 or E6

### Module F – Tracing back to foreground inputs
- Implied input scaling factor κᵢ from:
  `min Σ_S v_S·(λ_S·Σ_i P[i,S] − Σ_i κ_i·P[i,S])² + γ·Σ_i (ln κ_i)²`, with `v_S` = relevance of the sector.
- **Consistency measure** per input: weighted dispersion of the sector-wise implied factors `λ_S` over the sectors that input i carries by more than 50 %.
  - low dispersion and κᵢ ≠ 1: **E1**
  - κᵢ within ±10 % of a constant in U: **E1u**, with U = {10^±3, 3.6^±1, heating values 42–46 MJ/kg (oil, diesel), 36–50 MJ/m³ or MJ/kg (gas), 25–30 MJ/kg (coal), density 0.84–0.85 kg/l (diesel, light fuel oil), 0.95–1.0 kg/l (heavy fuel oil)}
  - high dispersion: **E2**, continue with Module G
- **E3 candidates:** for each significant μ_S, search bafu-2026 for activities whose cumulative inventory comes > 50 % from sector S and whose reference product fits the product context (spec evidence, sibling processes, keywords in the report). Rank by loss reduction in Module E.
- **E4 candidates:** inputs with κᵢ < 0.3 and low dispersion.

### Module G – Dataset substitution test (E2)
- For each input with more than 5 % share in a relevant sector or flow group, generate candidates:
  1. same reference product, other locations (including the location stated in the report)
  2. same CPC/ISIC, other technology or fuel mix
  3. sibling datasets from the spec evidence
- Replace column `M[:,i]` with `M[:,k]`, refit amount a_i once with fixed structure, and compare the loss of the Module E objective (λ=1, μ=0) and the tracer ratios.
- Additionally: plant location according to the report versus the locations of all inputs → list of location mismatches.

### Module J – Allocation and system boundary (E8)
- Fit a single scaling factor α on ĝ and compare the loss against the full Module E model.
- Cross-check with the allocation factors documented in the report (e.g. variants with and without allocation).
- System boundary: does the original contain infrastructure, packaging, transport or disposal that the model lacks? Check via the corresponding sectors (μ or λ).

### Module K – Plausibility against sibling processes
- For each input i: intensity `a_i` per unit of product versus the distribution of the same input class in BAFU unit processes of the same ISIC class.
- Output: `z = (ln a_i − median)/MAD`. Flag at |z| > 2 or factor > 10.
- Input classes present in more than 70 % of siblings but missing in the model (infrastructure, disposal, lubricants, explosives, water) are E3 candidates.

## 4. Hypothesis ranking

1. **Collect** from B, H, I, E, F, G, J, K. Each hypothesis h is a concrete model change: change amount, correct unit, swap dataset, add or remove input, change direct flow, correct mapping, apply α.
2. **Predicted effect** `Δĝ_h` computed in flow space; no database writes, only column operations in cumulative space.
3. **Score:**
   - `ΔL_h` = loss reduction (Module E loss at λ=1, μ=0)
   - `p_h` = evidence prior ∈ [0,1]: supported by the report 1.0; siblings or convention 0.6; statistical only 0.3. Optionally weighted with a strategy factor (see option in Section 2).
   - Physics check: balances from H must not get worse, and mass must remain feasible. Otherwise discard.
   - Score = `ΔL_h · p_h`
4. **Greedy forward selection:** at most 3 combined hypotheses; stop when the additional gain falls below 5 % of the initial loss.
5. **Report:** ranked list with evidence (tracers, κ, λ with CI, balance gaps) and the expected change in the categories.

**Rule:** Hypotheses are **never** accepted via amount calibration on category scores. Structural changes (E2, E3, E6, E7) take precedence over amount changes.

## 5. Validation by fault injection

Extend the existing benchmark (`benchmark.py`, cases with known ground truth) with targeted faults:

| Injection | Parameters |
|---|---|
| E1u | one input × {1000, 1/1000, 3.6, 42.6, 0.84} |
| E1 | one input × {0.3, 3} |
| E2 | location swap (CH↔DE↔RER) or technology variant |
| E3 | remove top input by climate contribution |
| E4 | add a plausible wrong input |
| E5 | remove direct flow or swap compartment |
| E6 | "burned in" plus duplicated direct CO₂ |
| E8 | global α ∈ {0.7, 1.4} |

- Metrics: top-1 and top-3 hit rate for (error type, affected input); false-positive rate on fault-free cases; calibration of the λ CIs.
- Acceptance (proposal): top-3 recall ≥ 80 % per error type, FP rate ≤ 10 %.
- Tune parameters (c, w_max, Huber kink, α, β, γ, sector granularity) on the benchmark, **not** on the three real cases.

### Final step: HTML results report

At the end, **one self-contained HTML report** is generated: `results/diagnosis/report.html`.
- Single file, all data embedded (JSON in a script block), charts via Chart.js or inline SVG, no external local files.
- Structure:
  1. Overview: X1–X3 and the top hypotheses per dataset
  2. one section per dataset with G1–G6 and the tables
  3. Methods appendix: parameters (c, w_max, Huber kink, α, β, γ), sector map (count, unassigned activities), flow selection per dataset
- Each chart has a one-line note on how to read it.
- Visibly mark illustrative or uncertain results (unstable according to A5).
- The machine-readable results (`<code>.csv`, `<code>.json`) are kept in addition.

## 7. Limitations

- Sector fingerprints from the model chain assume that the same sector behaves the same way in the original. This does not hold if the original's background uses a different database version (E9). If the background version named in the report is available, also build fingerprints from it and compare both variants.
- Very small or strongly mixed sectors are not identifiable. In that case, merge them and report the condition number.
- μ_S points to a missing sector, not to a specific dataset. Selecting the dataset requires evidence.
- The result is a prioritised list of hypotheses, not a proof. Confirmation comes from the report, the manufacturer or domain expertise.

## 8. Instructions for Claude Code (short form)

1. Extend `lci.System` to export `s`, `B` and the partition by input and activity; write tests.
2. Create `config/sector_map.yaml` (ISIC/CPC plus name rules) and report unassigned activities with their contribution.
3. Implement the modules in the order B → A → H → I → C → D → E → F → G → J → K → hypotheses → report, each with unit tests on a synthetic mini system (3–5 activities, known solution).
4. Hook `faults.py` into `benchmark.py` and run Section 5; tune parameters and report hit rates.
5. Then apply `diagnose` to the three real specs and generate `results/diagnosis/`.
6. No writes to `bafu-2026`; compute substitutions and hypotheses only in cumulative space.
7. Always compare `g` with the cumulative `ĝ`, never with the model's B column.
8. Finally, generate `results/diagnosis/report.html` with charts G1–G6 per dataset and X1–X3 across datasets (specification in Section 6).
